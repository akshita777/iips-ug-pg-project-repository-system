# 2. Stakeholder Analysis

## Actors

| Actor | Role | Key Actions |
|-------|------|-------------|
| Student | BCA/MCA student | Submit project, upload versions, view evaluation |
| Guide | Faculty mentor | Review submissions, approve/reject, guide students |
| Coordinator | Program coordinator | Allocate guides, manage workflow, override decisions |
| Evaluator | Internal/External examiner | Evaluate projects, assign marks, feedback |
| Admin | System administrator | Manage users, roles, system config |

## Stakeholder Matrix

| Stakeholder | Interest | Influence | Priority |
|-------------|----------|-----------|----------|
| Student | High | Medium | High |
| Guide | High | High | High |
| Coordinator | High | High | High |
| Evaluator | Medium | Medium | Medium |
| Admin | Medium | High | Medium |

## User Stories (Summary)
- As a **Student**, I want to submit my project with version history so that my progress is tracked.
- As a **Guide**, I want to review and approve submissions so that I can mentor effectively.
- As a **Coordinator**, I want to allocate guides based on preferences and capacity so that distribution is fair.
- As an **Evaluator**, I want to evaluate projects using a rubric so that assessment is consistent.
- As an **Admin**, I want to manage users and roles so that the system is secure.
